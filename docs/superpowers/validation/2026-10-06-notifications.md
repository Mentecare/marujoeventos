# EventCore notifications and public opportunity sharing — Task 4

This is additive source/migration work, not a hosted activation. There are no real deliveries, live DDL, active schedules or deployed changes claimed here.

Public `get_public_opportunity(p_service_id uuid) → jsonb|null` is granted to anon/authenticated. It returns exactly id/title/provider/role/days/region/date/description for an open, applicable, future opportunity with remaining capacity. Title/role use the specialty catalog or neutral service type, never the private event/client/custom role title. Private/closed/past/full identifiers return null. `/o/[id]` and its metadata use only this DTO, dynamic no-store fetches and no-store HTTP headers. The service worker excludes all previews, APIs, authenticated RSC, documents and auth-bearing requests from caching.

Authenticated caller-RPC API uses `commercialActor` (validated JWT, active profile, caller-scoped Supabase client). HTTP responses are private/no-store. All targets remain database-derived:

| Endpoint | Operation |
| --- | --- |
| GET `/api/notifications` | Center, current preferences, confirmed-email flag, own device IDs, adapter configuration status without values |
| PATCH `/api/notifications` | `{id}` marks only own notification read |
| PUT `/api/notifications/preferences` | Save own filters/cadence/channels/pause; enabling email requires confirmed auth.users address |
| GET `/api/notifications/devices` | Authenticated VAPID public key availability (no private credentials) |
| POST `/api/notifications/devices` | Validated owned browser PushSubscription; fixed HTTPS vendor origins/path, no arbitrary URLs |
| DELETE `/api/notifications/devices?id=…` | Disable own stored device |
| POST `/api/internal/notifications` | Strong >=32-byte bearer secret only; fixed bounded DB batches; request body never supplies targets/URLs |

RPCs: `get_notification_center()`, `save_notification_preferences(p_preferences jsonb)`, `mark_notification_read(p_notification_id uuid)`, `register_notification_device(p_subscription jsonb)`, `remove_notification_device(p_device_id uuid)`. Workers only: `claim_notification_batches(p_limit integer default 10)`, `recheck_notification_batch(p_batch_id uuid,p_lease_token uuid)`, `ack_notification_device(p_batch_id uuid,p_lease_token uuid,p_device_id uuid)`, `disable_notification_device` (same arguments), `finish_notification_batch(p_batch_id uuid,p_lease_token uuid,p_outcome text,p_reason text default null)`. Public service RPC ACLs exclude authenticated/anon, and each worker function checks auth.role=`service_role` defensively.

Preferences: mode `relevant|all_eligible`, specialty_ids UUID array, exact public regions text array (empty means all), inclusive ISO date_from/date_to, cadence `immediate|daily`, email_enabled/push_enabled, paused_until nullable timestamp. General eligible recipients follow active completed freelancer/active freelancer/specialty/capacity/public work criteria from canonical `apply_for_opportunity`, excluding own managed work. Email/push preferences never filter browsing or center. Direct invites/terms/status updates are participant-only. New commercial contracts notify active owners/explicitly finance-authorized members of the actual provider/buyer organizations; operation-only members are excluded. No event name/address/customer/pay data is included in direct notification text. Private helpers are not callable by application users.

Durability: trigger inserts source event + own center rows + unique `(notification_id,channel)` outbox rows in the same business transaction; source event keys make publication/invite status/term/contract dedupe durable. No historical backfill or mass resend. Daily work waits until next São Paulo midnight; up to 100 due items per recipient/channel become one durable batch. Immediate delivery creates one item per batch, at most five acknowledged batches per recipient/channel/hour. Claims serialize briefly with advisory transaction lock, use max20 batches and five-minute leases. HTTP worker claims five and reserves a 45-second adapter budget; no live worker is scheduled yet. Channel preferences/pause/confirmation/current participants/open status/capacity are rechecked at claim and before each adapter invocation. Invalid or stale recipients are suppressed. Six failed attempts (30-second exponential backoff capped at one hour) are retained as failed; crashed leases also consume bounded retries. Missing external credentials leave disabled queued batches with one-hour retry, zero false acknowledgments. Stored successful device receipts survive retries; 404/410 disables only the owned device. Email acknowledgment requires Resend 2xx plus nonempty provider message id; Web Push requires 2xx. `delivered` means provider accepted, not inbox/device display.

External prerequisites actually absent in controller's read-only metadata: `NOTIFICATION_DISPATCH_SECRET`, `NOTIFICATION_VAPID_PUBLIC_KEY`, `NOTIFICATION_VAPID_PRIVATE_KEY`, `RESEND_API_KEY`, `NOTIFICATION_EMAIL_FROM`; Resend account/key and verified sender domain; consenting physical test device; live migration and compatible verified endpoint; active pg_cron/pg_net configuration/Vault schedule. Existing Supabase URL/publishable/service key are reused only at their existing boundaries. VAPID private key, dispatch and Resend keys are server-only variables. `NOTIFICATION_EMAIL_FROM` must be a Resend-verified sender; never use a connected personal mailbox as a substitute. VAPID subject is a responsible mailto/HTTPS contact.

Scheduler: official Vercel Hobby supports once-daily cron (per-hour precision), so minute dispatch uses Supabase pg_cron + pg_net + existing Vault. No plan upgrade or cron stanza is added to Vercel. Controller must first apply the reviewed migration, configure new credentials, deploy and prove HTTPS authorization/refusal, then configure the fixed URL and secret in a secure controller process environment and run `psql -X --file=scripts/setup-notification-scheduler.sql` with `ON_ERROR_STOP` already in the script. Required environment names: `EVENTCORE_NOTIFICATION_WORKER_URL`, `EVENTCORE_NOTIFICATION_DISPATCH_SECRET`, optional `EVENTCORE_NOTIFICATION_BYPASS_SECRET_NAME` (set empty for production). The latter refers to an existing narrowly scoped Vault secret name for a temporary preview protection bypass; no token enters cron command text. Activation accepts only eventcore.space or the existing marujoeventos preview deployment hostname family, exact worker path and HTTPS. Preview protection may still require a real scoped bypass and end-to-end proof. Setup installs available pg_cron/pg_net and retains named Vault configuration, but has not been executed by the implementer.

Recovery: execute `scripts/recover-notification-scheduler.sql` to unschedule only. Preserve all user preferences, outbox rows, batches and receipts. Restore verified configuration and rerun setup to resume; expired leases reclaim automatically. Investigate failed provider batches, then repair only explicitly reviewed batch IDs using the commented scoped statements. Resend idempotency uses stable `eventcore-{batch_id}`; its documented retention is 24 hours, so a replay beyond retention can duplicate. Web Push is at least once across provider-ack/process-crash boundaries; no exactly-once guarantee is claimed. Never reset receipts or mass retry suppressed jobs. Feature rollback can remove callers/revoke worker RPCs while preserving all additive data; keep upstream finance/operations helpers and historical records unchanged.

Push UX: only the explicit activate button requests notification permission. No signup/install prompt. Denial/unsupported browsers retain center, email and opportunity browsing. iOS/iPadOS 16.4+ requires an app added to Home Screen and opened through its icon; feature detection controls support. Android and other browser support depends on browser/permission. No universal or physical delivery claim. notificationclick accepts only exact internal `/o/{uuid}`, `/?opportunity={uuid}`, `/?assignment={uuid}`, `/?contract={uuid}`; auth then revalidates eligible opportunity or own work/authorized commercial workspace. Unsafe additional params/redirects/external links are rejected.
