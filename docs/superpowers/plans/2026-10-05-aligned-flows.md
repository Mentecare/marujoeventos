# EventCore aligned flows implementation plan

Spec: `docs/superpowers/specs/2026-10-05-aligned-flows.md`.
Goal: implement the approved B2B hiring, private work/finance, identification, real histories, notifications and branded quotations in the existing EventCore with a verifiable homologation build.
Architecture: incremental Supabase migrations and canonical authorization helpers; existing event/assignment/proposal tables extended compatibly; role-scoped RPC DTOs consumed by focused React components; authenticated Next server endpoints for PDFs/Push and a durable notification worker.
Stack: existing Next 15, React 19, TypeScript, Supabase/Postgres 17, Sharp and PWA. Add pinned maintained Node dependencies only for Web Push/PDF when needed.
Execution: sequential implementation agents with scoped review, then one whole-branch review. Controller applies reviewed migrations and validates actual Supabase fixtures. Publication follows existing Git/Vercel infrastructure; do not create a replacement project.

## Global Constraints

- Preserve the existing application, approved interface/navigation, profiles/data/authentication/domain/Google Agenda/storage and migration history; no project restart.
- Agencies/scenography buyers hire companies/teams; only providers hire freelancers. Enforce this in RPCs, raw writes, RLS and APIs, not only UI.
- Sale prices and freelancer remuneration are independent. Buyers never see wages/internal costs/margin; workers never see client sales/colleague wages/company result; coordinators require explicit finance permission; unrelated organizations see no private contract data.
- Preserve historical totals and records; historical unclassified/unowned records are not silently reclassified. Unknown financial/reputation/attendance values remain unknown. Functions/days/initial function conditions are defined only at work creation.
- New work is private unless opportunities are explicitly published. Origin and visibility are independent. Base/team membership never implies job acceptance.
- A single required “CPF ou CNPJ” accepts valid CPF, numeric CNPJ and alphanumeric CNPJ; document entry is not identity verification; full CPF is not public; existing undocumented accounts retain access/history.
- Use confirmed real work for relationship histories/reviews, recorded evidence for punctuality, independent metrics/counts and deterministic documented ordering.
- Notifications, shared previews and PDFs must enforce the same tenant/participant privacy. No general alerts for private jobs, no live mass notification/email tests, no false “sent” result without a real adapter response.
- PDF uses sale prices only, correct Brazilian totals/dates, every-page EventCore watermark/footer and authorized download. Unit-price visibility changes presentation, never totals.
- Validation example: ten workers, two days, sale R$280/day yields R$5,600; pay R$220/day yields R$4,400; each worker R$440; estimated difference R$1,200 before other expenses/taxes.
- No secrets in commits, response bodies, logs or reports. No live DDL application/deployment by implementers; controller coordinates those after review. Every migration needs an explicit recovery path preserving data.

## Review Focus

1. Buyer bypass through old staff RPCs or direct table writes (Tasks 1,2,6).
2. Raw row/DTO/API/PDF/cross-tenant leaks and automatic multiplication of historical pay (Tasks 1–6).
3. Private origin becoming public, base membership becoming acceptance or fictitious reputation (Tasks 2,4,6).
4. Notification duplicate/stale sends, unsupported push blocking browsing, missing adapters falsely reporting delivery (Tasks 4,6).
5. Quote totals/pagination/unit-toggle, malicious guessed identifiers and migration/legacy UI compatibility (Tasks 1,3,5,6).
